## PlcApiServer 실행 가이드

### 📌 준비 사항
- .NET 8 SDK 설치 필요
- MariaDB/MySQL 연결 설정 (appsettings.json 확인)

---

### 🚀 실행 방법

#### 1️⃣ **개발 모드 (DEBUG)**
```
run.bat 더블클릭
```
- 디버그 정보 포함
- 빠른 개발 사이클
- 포트: http://localhost:5050

#### 2️⃣ **릴리스 모드 (최적화)**
```
run-release.bat 더블클릭
```
- 성능 최적화됨
- 프로덕션 환경에 적합
- 포트: http://localhost:5050

#### 3️⃣ **빌드만 하기**
```
build.bat 더블클릭
```
- 출력: `bin\Release\net8.0\`

#### 4️⃣ **배포용 패키지 생성**
```
publish.bat 더블클릭
```
- 출력: `publish-output\`
- 이 폴더를 다른 곳에 복사해서 `PlcApiServer.exe` 실행 가능

---

### 📋 각 .BAT 파일 설명

| 파일 | 용도 | 실행 시간 |
|------|------|---------|
| `run.bat` | 개발 중 테스트 실행 | ~3-5초 |
| `run-release.bat` | 최적화된 실행 | ~3-5초 |
| `build.bat` | 빌드만 수행 | ~2-3초 |
| `publish.bat` | 배포 패키지 생성 | ~3-5초 |

---

### 🌐 API 확인

서버 실행 후 브라우저에서 다음 주소로 접근:
```
http://localhost:5050/api/plc/config
```

### 📝 로그 파일 위치
- `D:\SC_LOG\` - PLC 통신 재연결/실패 기록 (COMM 태그, 실패 발생 시마다 즉시 기록 — 실패가 없으면 그날 파일 자체가 생기지 않음)
- `D:\ER_LOG\` - 통신 실패 상세(FAIL, 발생 즉시) + 매 정각 지난 1시간 요약(HOURLY) 하트비트

---

### ❌ 문제 해결

**포트 5050이 이미 사용 중이라면:**
1. 기존 서버 프로세스 종료
2. 또는 `Program.cs`의 포트 번호 변경 후 빌드

**데이터베이스 연결 오류:**
1. `appsettings.json` 확인
2. 연결 문자열(ConnectionString) 수정

### 🔄 자동 시작 및 워치독

Windows 작업 스케줄러의 `PlcApiServer Watchdog` 작업이 사용자 로그인 시 워치독을 시작합니다.
워치독은 30초마다 `/health` 응답과 서버 프로세스를 확인하고, 프로세스가 없으면 Release 실행 파일을 시작합니다.
프로세스는 살아 있지만 상태 응답이 연속 2회 실패하면 해당 프로세스만 재시작합니다.
PLC 연결 상태는 프로세스 생존 여부와 별개로 취급하므로 PLC 연결 오류만으로 서버를 재시작하지 않습니다.

워치독 상태는 Windows 알림 영역(작업표시줄 시계 옆)의 아이콘과 툴팁으로 표시됩니다.
아이콘을 더블클릭하면 API를 열고, 마우스 오른쪽 버튼 메뉴에서 로그 열기, 서버 재시작, 워치독 종료를 할 수 있습니다.
워치독 로그는 `watchdog.log`에 기록됩니다. 작업을 실행하려면 PC 재시작 후 Windows에 로그인해야 합니다.
로그인 전에 서비스가 시작되어야 하거나 사용자 계정이 로그아웃된 상태에서도 계속 감시해야 한다면,
관리자 권한으로 Windows 서비스 또는 SYSTEM 작업으로 등록해야 합니다.
